# Mumbai Public Works: data changes

The dashboard is public and names real people and companies. Wrong data can harm them and
destroys trust in the site. Every change follows the process below. No exceptions for
"small" edits to people or companies.

## What lives where

| file | contents | stakes |
|---|---|---|
| `public-works/data/projects*.js` | projects (schema in `public-works/README.md`) | medium |
| `public-works/data/routes.js` + `points` in batch files | approximate map points | low |
| `public-works/data/mla-profiles.js` | affidavits (ADR), Praja scores, MLA work and news | **high** |
| `public-works/data/contracts.js` | contractor and agency records, documented events | **high** |
| `public-works/data/delays.js` | blockers, spend, documented delay costs | medium |
| `public-works/data/yojanas.js` | schemes | medium |
| `public-works/data/tenders.js` | generated by `tools/scrape_mahatenders.py`; never hand-edit | low |
| `public-works/data/wards.js` | BMC ward boundaries | low |

Project `constituencies` are hand-mapped from each project's localities. Do not switch to
computing them from a boundary file unless that file scores 100% on
`node public-works/tools/test-ac-boundaries.cjs <file.geojson>`. The freely available
DataMeet file failed (27/38) and would have attributed projects to the wrong MLAs.

## The process

1. **Research (pass 1).** Give a researcher the brief that fits:
   - new projects: `public-works/research/brief.md`
   - anything about named people: `public-works/research/brief-people.md`
   - contractors and awarding bodies: `public-works/research/brief-contracts.md`

   Pass the list of what already exists so nothing is duplicated:
   ```bash
   node -e 'const {loadAll}=require("./public-works/tools/validate.cjs");const {D}=loadAll();console.log(D.projects.map(p=>p.id+" | "+p.name).join("\n"))'
   ```
   Researchers write to the scratchpad, never straight into `public-works/data/`.

2. **Verify (pass 2), required for every high-stakes item.** A different agent, given
   `research/brief-verify.md` (plus `research/brief-verify-mla.md` for MLA items),
   re-opens every source and returns `confirmed | fix | remove` per claim. Apply its
   verdicts. Unchecked claims are dropped, not published. Set `verified: "<date>"` on every
   item that passes; the page shows "source re-checked <date>".

3. **Editorial rules.** These hold even when a verifier confirms something:
   - Legal status exactly as the source says: named in FIR ≠ chargesheeted ≠ convicted;
     bail ≠ acquittal; a shortened blacklisting is not "Cleared"; a dismissed case leads
     with the dismissal.
   - Name individuals only when formally charged, arrested, convicted, suspended or named
     in an official order. Never attribute cases to an MLA's associates without a report
     that formally links them.
   - No allegations from activists' preliminary tallies, party press releases or
     aggregator summaries (e.g. MumbaiVotes); re-source to the original outlet or drop.
   - Uniform coverage: don't publish a category (e.g. post-election cases) for some MLAs
     and not others. Hold it back until every MLA has been checked the same way.
   - Never estimate a missing number. `null` shows as "not published".
   - Don't present derived arithmetic as a cost of delay.

4. **Validate and look.** `node public-works/tools/validate.cjs` must pass. Then open the
   affected views (desktop and ~390px width) and check nothing overflows.

5. **Publish.** Commit with a message that states what was checked and what was removed.
   For the claude.ai page, run `node public-works/tools/build-artifact.cjs <out.html>` and
   publish it with the `public-works/` files.

## Keeping it current

- Tenders refresh daily via `.github/workflows/public-works.yml` (after merge to the
  default branch).
- `validate.cjs` warns about projects not re-checked in 180 days
  (`--stale-days=N` to change). Re-research stale "Delayed", "Stalled" and pending-case
  items first.
- Ward officers and agency heads change often; re-check `wardInfo` and `agencyHeads`
  against BMC's Assistant Commissioner list every few months.
